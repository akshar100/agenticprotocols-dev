Latency budget
No patterns in this family

Every entry carries two separate figures, because they are two different things. Total cost is tokens burned. Path depth is sequential model calls on the critical path — what the user actually waits for. They come apart badly: ensembling and debate both cost about 5×, but ensembling is one call wide and debate is four calls deep, so only one of them survives a live interaction. Latency is therefore not a fifth axis here. The four axes are positions you choose; a latency budget is a constraint you are handed, so it filters rather than ranks, and it is drawn in red to keep the difference visible. Both figures are order-of-magnitude estimates relative to a single reason–act loop on the same model, not measured benchmarks. The survey's own conclusion applies: controlled, cost-matched comparisons that isolate architecture from model capability barely exist, so treat every number here as a prior to be overturned by your own evaluation.
